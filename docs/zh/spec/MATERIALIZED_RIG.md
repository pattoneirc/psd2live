# 固化 Rig：以作者态 Rig 为权威数据的工程模型

[文档目录](../../README.md) · [文档层](DOCUMENT_LAYER.md) · [工程格式](PROJECT_FORMAT.md)

> 状态：**部分实现**。阶段 0、阶段 1–2 的核心与阶段 3 的追加编辑已实现（见[实现进度](#10-实现进度)），其余为设计。本页给出目标模型、存储、操作分类、再生成合并规则与分阶段计划；实现后各部分的事实写回 [文档层](DOCUMENT_LAYER.md) 与 [工程格式](PROJECT_FORMAT.md)。

## 1. 背景

### 1.1 现状

`PuppetModel` 不保存。每次打开、撤销、切换历史或提交编辑时：

1. `RigBuilder` 按**当前代码**和**当前设置**从源图生成基础 Rig（含骨架烘焙、v2 拆分部件的停放）；
2. `RigEditOverlay.applyTo` 在其上依次重放旧格式静态编辑与 `authoringJournal`；
3. 摆动、模拟写回、`skeleton.skin` 与生成结果覆盖按 `DocumentGenerators` 的图运行，再生成物理与动作。

日志条目按 ID 引用生成的变形器、参数与网格，部分条目（`vertex_group_put`、`canvas_geometry`、`set` 的顶点位移、路径、Glue 顶点对、拆分记录）还按**顶点下标**引用。条目只在写下它的那一刻、那一份基础 Rig 上才确定成立；之后基础 Rig 的结构一变，它就可能找不到目标，或静默作用到错误的对象上。

### 1.2 结构漂移的来源

| 来源 | 例子 |
| --- | --- |
| 生成设置 | 开启头发模拟删除 `DeformHair*Physics` 与 `ParamHair*`；启用骨架不再生成手臂下垂 Warp 与左右成对 Warp；`runtimeTarget` 让骨骼与模拟参数在关键形轴与混合形之间切换 |
| 骨架 | 绑定网格改挂到骨骼旋转、插入关节行（顶点数变化）、折叠无网格的链接骨骼 |
| 拆分与源图 | 部件取代原网格；新部件参与框架生成，改变其他对象的框架 |
| 生成代码本身 | 任何生成规则、默认网格、ID 派生的修改都会改变旧工程的基础 Rig |

### 1.3 为保住重放已付出的代价

现有保护机制，每一项都只覆盖一部分情形：

- 冻结生成输入：`generationSource`、`meshSource`、`mesh_generation_baseline`（网格设置）；
- 生成迁移：`RigGenerationMigration` 在设置/分类变化时把迁移写成日志记录 `rig_generation_transition`（内含整份生成 Rig 的 JSON），保留退役对象；
- 父级不再生成：`VanishedParent`、`ArtPrimitiveJournal.rehome`、结构编辑 `bind`/`move` 的跳过；
- 拆分：v1/v2 两套 `art_primitive` 记录，v2 的乘客、停放（`PrimitiveSkins`）、两遍捕获、乘客容错（`StubTolerance` / `SupersededEntryNote`）、骨架烘焙前解码部件（`skinnable`）；
- 骨架：`SkeletonCanvasSkin.lockedTopology`、`handEditedTopology` 拓扑锁、日志安放网格的事后蒙皮；
- 性能：`ReplayCheckpoints`、`GeneratorReuse`、阶段缓存与头部缓存，都是为了让每次重放足够快。

近期同类修复（2026-10-07 至 10-08）：`7f30f7aa`（头发模拟删 Warp 后 v2 部件父级缺失）、`2d6d0b7d`（启用骨架后手臂下垂 Warp 消失）、`36d6fbb5`（日志改变骨架烘焙读取的内容时不能在缓存基础上续放）、`5019b69b`（骨骼绑定网格被日志改挂）、`29099a3a`（部件在骨架烘焙之后才出现）、`220c7d5a`（预设重建基础时部件被当普通图层生成）、`ea226c07`（v1 部件不在上一次生成中）、`a08df353`（v2 部件的父级链编辑被应用两次）、`3c36db5a`（生成输入冻结前加入的图层被静默重新生成）。

### 1.4 尚未覆盖的缺口

按“生成设置改变结构、而日志已有引用”排查的结果：

| 触发 | 失效的条目 | 现有保护 |
| --- | --- | --- |
| 头发模拟开关 | 以 `ParamHair*` 为键或以 `DeformHair*Physics` 为目标的 `set`、`canvas_geometry`、重命名、面板编辑、其下新建的 Warp 报错；该 Warp 上的 `set` 静默跳过 | 仅 `bind`/`move` 与拆分部件改挂；`RigGenerationMigration.settingsChanged` 不含这两个开关 |
| 恢复经典摆动、删除模拟 | 以模拟输出参数为键的条目报错 | 无 |
| 启用骨架、增删骨骼 | 消失的成对 Warp 与骨骼上的条目报错；关节行使 `vertex_group_put`、`set` 位移、`canvas_geometry`、`path_put` 顶点数不符；Warp 下记录的归一化位移换到骨骼空间后静默错位 | 拓扑锁只看 `canvas_topology` 与日志安放的网格；带顶点组的普通绑定网格不锁 |
| `runtimeTarget` | `set` 静默改走混合形路径；混合形参数上的 Glue 关键形报错 | 无 |

除上述容错路径外，任何一条重放失败都使整次重建失败，错误只有一条消息：提交被拒绝，打开工程或切换历史时得不到模型。

### 1.5 与原设计的差距

`docs/local` 中的格式设计第 4 节要求“文档层只保存声明式的状态，打开工程时不再靠重放命令重建模型；命令历史保留，只用于撤销和分支”，v1 迁移时“用当前版本重放一次，把结果固化保存”。已落地的部分：内容哈希、生成器依赖图、生成缓存、三方合并、按内容寻址的 v2 归档；覆盖与三方合并只接入了摆动、模拟与 `skeleton.skin`。未落地的是核心一步：v2 节点保存的仍是“源图 + 设置 + 日志”，基础 Rig 每次按当前代码重新生成（[文档层 · 后续](DOCUMENT_LAYER.md#后续)、[路线图](../ROADMAP.md)）。

## 2. 目标与非目标

**目标**

- 打开、撤销与切换历史直接从修订保存的固化 Rig 得到模型；生成代码或生成设置的变化不影响已保存修订的打开。
- 编辑命令在提交时对当前模型执行一次，结果随修订保存；命令只需在执行时的模型上成立。
- 改变生成输入是一次显式的再生成事务：重新生成后把用户的修改合并上去，合并不了的情况作为结构化问题报告，在提交前可预览，而不是在打开时崩溃。
- 生成器的改进不再自动改写旧工程；由用户发起“更新生成”。

**非目标**

- 不取消命令：GUI 与 MCP 仍共用同一套 JSON 命令与原子批量，提交边界（候选 → CAS → 一个历史节点）不变。
- 不把所有编辑改写成“生成结果 + 覆盖”：只有每次求值都会重跑的修改器（摆动、模拟写回、`skeleton.skin`）才使用覆盖。
- 不保存预览运行包、纹理集页面或物理、动作的生成结果。

## 3. 模型

```
文档输入 ──(再生成事务)──▶ G 生成快照 ──┐
                                          ├─ 三方合并 ─▶ M 固化 Rig ──▶ 修改器 ──▶ 预览 / 导出
编辑命令 ─────────────(直接作用)────────────────────────┘
```

| 对象 | 内容 | 现在的对应物 |
| --- | --- | --- |
| **M 固化 Rig** | 作者态 Rig：基础生成（含骨架烘焙）加上全部编辑，摆动、模拟写回与覆盖合并之前。纹理坐标为画布单位（未绑定纹理集） | `RigEditOverlay.authored(BuiltRig)` 的结果 |
| **G 生成快照** | 上一次再生成时生成器的输出，未经编辑；只作再生成合并的公共祖先 | `BuiltRig.resolvedPuppet()`（去乘客、放入部件）的未绑定形式 |
| **生成元数据** | 网格 → 源图层映射、部件槽与中性边界、面部中心与半径、生成器版本、生成输入摘要 | `BuiltRig` 中 `puppet` 以外的字段 |
| **修改器** | `skeleton.skin`、摆动、模拟写回、生成结果覆盖合并、物理组、生成动作 | `DocumentGenerators` 中日志之后的节点 |

- **打开**：读取 M 与元数据 → 分析源图（分类，供界面与预设使用）→ 打包并绑定纹理集 → 运行修改器 → 编译预览。
- **G 只在再生成时读取**，打开时不解码。

## 4. 操作分类

| 类别 | 操作 | 处理 |
| --- | --- | --- |
| A 直接编辑 | `canvas_geometry`、`canvas_topology`、`canvas_create_warp/rotation`、Glue 的创建与编辑、`path_put/delete`、`vertex_group_put/delete`、关键形 `set/copy/delete`、`parameter_keys`、`structure`（含参数增删改、绑定、移动、重命名）、`warp`、`canvas_mesh_create`、网格显隐与材质 | 命令按现有 `apply` 语义（严格，不跳过缺失目标）作用于 M；G 不变 |
| B 再生成事务 | 网格设置、嘴型等生成设置、头身强度与 `rigTuning`、分类与父级覆盖、图层增删与恢复、拆分、需要重建网格的绘画与换图、画布矩形移动、骨架定义、头发模拟开关、`runtimeTarget`、更新生成器版本 | 重新生成 G′，按第 5 节合并出 M′，得到 (G′, M′) |
| C 修改器设置 | 摆动、模拟（含烘焙结果）、物理组与顺序、帧率、生成动作与片段 | 只改文档中的修改器设置；M、G 不变 |
| D 绑定与导出 | 纹理密度、预算、固定位置、图集排布，不重建网格的绘画与换图，导出设置 | 只影响纹理集绑定或导出；M、G 不变 |

- A 类的候选为“在 M 上执行命令 + 运行修改器”；画布拖拽预览同样在 M 上套用待提交命令。
- B 类在锁外计算，报告进度并检查原协程取消，提交规则与现有重建型提交相同。
- 历史节点保存所执行的命令，用于显示、审计与 MCP，不再用于重建。

## 5. 再生成合并

输入：公共祖先 G、新生成 G′、当前 M。输出：M′ 与问题列表。对象按稳定 ID 对齐（参数、部件、变形器、网格、带 ID 的 Glue、路径；顶点组按“网格 + 名称”；无 ID 的 Glue 按网格对）。判断“用户改过”一律按 M 与 G 的位相等，M 与 G 都是保存值，没有重新计算带来的浮点误差。

| 情形 | 规则 | 报告 |
| --- | --- | --- |
| 只在 M 中（用户创建） | 保留。父级在 M′ 中不存在时，沿它在 G 中的祖先链找到 G′ 仍有的最近祖先改挂，默认姿态下的画布位置不变，关键形位移按父级空间的线性部分换算 | `rehomed` |
| G 有、G′ 无 | M 中该对象与 G 相同：删除；不同：保留为退役对象 | `retired_kept` |
| G 有、M 无（用户删除） | 保持删除，即使 G′ 仍生成它 | — |
| G′ 新增 | 加入 | — |
| 三者都有：字段 | 逐字段三方合并：用户未改的跟随 G′，生成未变的保留用户值，两边都改时保留用户值 | `conflict` |
| 三者都有：父级 | 用户未改父级而 G′ 改了：跟随 G′，按画布位置不变换算局部坐标与关键形 | `reparented` |
| 三者都有：关键形 | 轴取并集；逐格、逐顶点（或控制点）三方合并 | `conflict` |
| 拓扑不同（G 与 G′） | 用户差值 M − G 经画布纹理坐标迁移（`RasterMeshJournal.prepare` 的顶点来源）到 G′ 的拓扑上再加回；顶点组、路径、Glue 顶点对随同一迁移计划移动（沿用 `MaterializedMeshRebuild`） | `topology_migrated` |
| 用户改过拓扑（M 与 G 拓扑不同） | 保留用户拓扑；G′ 相对 G 的生成变化经迁移计划映射到用户拓扑 | `topology_kept` |
| 参数被 G′ 删除而 M 中有引用 | 保留参数为退役参数及其上的用户关键形 | `retired_kept` |

- 问题以结构化记录报告（类型、对象、原因代码、点数），经 `QualityRule` 定级、`QualityFence` 放行：合并后几何无效等为 error 并阻断；改挂、退役、冲突为 warning，可提交。
- B 类操作支持试运行，返回合并报告而不提交。
- 合并框架复用 `format-compile` 的 `ThreeWayMerge`（MIT），结构规则写在产品层。

### 5.1 用此模型重述现有特例

- **拆分**：源图改变（原图层由部件取代）的 B 类事务。部件继承原网格的用户差值（M − G，经分区的顶点来源）；G′ 中部件是普通图层的生成结果。v2 两遍捕获的目的（部件参与生成、记录只存生成之外的作者数据）在一次合并中达成，乘客、停放与拆分记录的重放机制随之退出日常路径。
- **骨架**：骨架烘焙属于生成器，输出进入 G。改骨骼是 B 类事务（沿用按肢体重烘焙）；关节行是拓扑迁移，用户在绑定网格上的修改按合并规则带过去，不再需要拓扑锁与烘焙前解码部件。用户把绑定网格改挂到非骨骼变形器时，仍由修改器 `skeleton.skin` 蒙皮。
- **头发模拟、手臂下垂 Warp 消失**：G′ 中变形器消失，其下的用户对象按“只在 M 中”改挂，对应 `VanishedParent` 的通用形式。
- **生成迁移**：`rig_generation_transition` 把迁移写进日志并在每次重放时执行；改为一次性合并后，迁移结果直接是 M′。

## 6. 存储（工程格式 v3 草案）

在 v2 归档上增加 Rig 对象，修订索引升级 schema：

| 路径 | 内容 |
| --- | --- |
| `rig/objects/<类型>/<sha256>.bin` | 单个对象的持久编码：参数列表与参数树、部件树、每个变形器、每个网格（网格、关键形、通道、混合形）、Glue、路径、顶点组、画布与元数据 |
| `history/revisions/<key>.json` | 新增 `rig: {materialized: {...}, generated: {...}, meta}`，列出 M 与 G 的对象哈希；不同修订、M 与 G 之间按内容共享对象 |

- **编码**：基于中立 IR（`format-model`，MIT）定义带 schema 版本的持久编码，配向前迁移与语料回归测试。`RigIrBinary` 是缓存格式，只接受自身版本，不作持久格式；浮点同样按原始位保存。
- **纹理**：M、G 保存画布单位纹理坐标，打开时按纹理集绑定（沿用 `UvBinding` 的换算），纹理集仍由文档决定。
- **体积**（tml，单个整 Rig，`RigIrBinary`）：

| | 原始 | deflate | 解码为 `PuppetModel` |
| --- | ---: | ---: | ---: |
| 无骨架 | 约 336 KB | 约 174 KB | 约 3.5 ms |
| 自动骨架 | 约 7.1 MB | 约 5.6 MB | 约 26 ms |

  骨架 Rig 的体积主要是骨骼参数上的网格关键形，浮点压缩率低。按对象寻址后，A 类编辑只写被改的对象；重烘焙骨骼会重写所在肢体的绑定网格。
- 日志节点照常保存，作为命令记录。

## 7. 兼容与迁移

- **打开 v2 工程**：头部修订用现有重放管线（冻结为旧版重放路径）重放一次，得到 M 与 G 并在下次保存时写出；重放失败时以修复状态打开，列出失败条目，允许切换到更早的修订。
- **其他修订**：在首次切换到它时按同一路径固化；未固化的修订保留 v2 文档节点。
- **旧版重放路径**：v1/v2 拆分记录、旧格式静态字段、生成迁移记录、`VanishedParent` 与乘客容错移入单独的包，只做修复，不再随新功能扩展；用已保存的工程（`legacy-split.psd2live`、`v1-sample.psd2live`）按 IR 哈希锁定。它仍调用当前的生成代码，所以旧修订的固化结果可能随生成代码变化，但每个修订只固化一次。
- **缺少 G 的修订**（固化前的旧修订、导入后首次再生成）：以当前代码对保存的生成输入重新生成作为 G。生成代码的差异因此被视为用户修改而保留，不会丢失数据。
- **导入的 CMO3 模型**：G 为导入基线，不参与再生成。

## 8. 分阶段计划

每阶段按功能验收链路验收：领域数据 → 历史 → 保存恢复 → 目标版本 → 导出读回 → 视觉检查（见[运行时与导出边界](RUNTIME_EXPORT_ARCHITECTURE_AND_GAPS.md)）。

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| 0 止血（独立） | 头发模拟删除旧摆动 Warp 时拆分部件随基础网格改挂；骨架拓扑锁计入按细分前顶点数写下逐顶点记录的绑定网格 | 已有工程在两种开关下可重建；对应回归测试 |
| 1 影子固化 | 保存时在可删除的缓存目录写出 M、G 对象；打开仍重放。开发工具对比重放结果与保存的 M，收集不一致语料；测量体积与耗时 | 旧程序照常打开；`ExportGoldenTool` 逐字节一致 |
| 2 以固化结果打开 | M 成为打开与切换历史的权威数据，修订索引升级 schema；编辑仍经现有重建管线得到候选，再写出 M | 打开路径不经过 `RigBuilder`；生成代码改动不影响已固化修订；v2 工程迁移测试 |
| 3 直接编辑 | A 类命令直接作用于 M；提交只在 M 上执行命令，与基础重建和重放检查点无关 | A 类提交耗时与日志长度无关；GUI 与 MCP 行为一致 |
| 4 再生成合并 | 实现第 5 节合并与问题报告；B 类操作逐项迁入（设置与分类 → 头发模拟 → 骨架 → 拆分 → 网格重建）；增加“更新生成”与试运行 | 第 1.4 节每一行都有合并测试；新编辑不再写 `rig_generation_transition` 与 `art_primitive` |
| 5 清理 | 重放检查点、乘客与停放、骨架前解码部件、生成迁移记录仅留在旧版重放路径；文档改写 | 热路径不再引用旧版重放包 |

### 8.1 测试

- 固化一致性：对测试语料，以固化结果打开与经重放重建得到相同的 IR 哈希。
- 合并：在手写小 Rig 上覆盖第 5 节每条规则（变形器消失、参数删除但有用户关键形、关节行插入、用户拓扑与生成拓扑同时变化、用户删除的生成对象、用户创建的 Warp 父级消失）。
- 格式：v3 拆分与拼回无损、对象共享、schema 迁移、旧程序拒绝打开更高 schema 而不丢字段。
- 在示例 PSD 上跑整条流水线的对比做成开发工具，不进全量测试。

## 9. 风险与待定

- **体积**：骨架频繁调整的长历史会积累多份绑定网格，需要实测；可选措施是只为分支末端与头部保留 G，其余修订缺 G 时按第 7 节回退。
- **生成改进不再自动生效**：需要在界面上提示工程使用的生成器版本，并提供“更新生成”入口与试运行报告。这是产品层面的取舍。
- **分类仍随代码变化**：打开时分析源图的结果只影响界面与预设，不影响 M；预设在执行时读取当前分析，属于 B 或 C 类操作。
- **内存**：每个历史节点的 M 用软引用缓存，未命中时从存储解码（骨架 Rig 约 26 ms）。
- **MCP**：公开命令不变；新增再生成试运行与 `workspace_inspect` 中的合并问题，需声明严格的 `resultSchema` / `jobResultSchema`。
- **待定**：`generationSource` 冻结在固化后是否保留（再生成默认用冻结像素还是当前像素）；绘制顺序覆盖与父级覆盖归 A 类还是 B 类。

## 10. 实现进度

**阶段 0（已实现）**

- 骨骼绑定的网格，若日志中按顶点下标的记录全部按细分前的顶点数写下，骨架不再为它插入关节行（`SkeletonCanvasSkin.lockedTopology`），见[文档层 · 日志安放的网格](DOCUMENT_LAYER.md#日志安放的网格)。
- 头发模拟删除旧摆动 Warp 时，v2 拆分部件与基础网格一起改挂到跟随 Warp（`RigBuilder`）。没有采用“保留静止 Warp”：那会改变已烘焙头发模拟所在的父级空间。

**阶段 1–2（核心已实现）**

- 重放拆成两段（`RigEditOverlay.replayAuthored` / `finish`）：`BuiltRig.authoredRig` 给出作者态 Rig（`AuthoredRig`：作者态 puppet、日志创建网格的映射、需应用图层显隐的网格），`AuthoredRig.finished` 运行修改器、覆盖合并、延后面板编辑、显隐与绘制顺序。`withRigEdits` 即两段相接，导出与此前逐字节一致（`ExportGoldenTool`）。
- `RigPreviewModel` 的基础 Rig 与作者态 Rig 由 `PreviewRigSources` 提供：生成构建已知基础 Rig，作者态在首次使用时由重放检查点给出；由作者态构建的模型只在有人读取 `baseRig` 时才生成基础 Rig。
- `PSD2LivePipeline.materializedPreview`：由作者态 Rig 构建预览，只做源图分析与纹理集打包，不运行 `RigBuilder`、骨架烘焙与日志重放；纹理集绑定键不同时返回空，由调用方照常构建。延迟删除（软删除图层）的文档同样支持；导入 CMO3 的模型不支持。
- 按修订的存储（`project/MaterializedRigStore`）：本进程构建过的修订（软引用）与打开归档读到的修订。`WorkspacePreviewBuilder.build` 先查存储（打开、切换历史、撤销），除非当前模型能更便宜地更新（见阶段 3，或基础 Rig 已在手、只是编辑覆盖层）；保存把可得的修订写入归档 `rig/`（格式见[工程格式 · 作者态 Rig](PROJECT_FORMAT.md#作者态-rig)）。
- 持久编码：`RigIrObjects`（MIT）把中立 IR 拆为框架、变形器与网格对象，按版本可读；`MaterializedRigCodec` 写头部。

**阶段 3（追加编辑已实现）**

- 新文档的作者态阶段输入与当前模型相同、只在日志末尾追加了条目（`RigEditOverlay.extends`，追加的不是 `art_primitive` 记录）时，`PSD2LivePipeline.updateRigEdits` 把追加的条目按重放语义作用于当前作者态 Rig（`appendedTo`），再运行收尾阶段；不读取基础 Rig，也不重放此前的条目。结果的基础 Rig 沿用当前模型的（仍按需生成）。
- 提交路径上不再无谓地生成基础 Rig：生成结果覆盖的捕获只在日志有 `art_primitive` 记录时才读取基础 Rig 的拆分部件（`RigPreviewModel.primitiveSkins`）。
- 由作者态 Rig 打开的工程，画布与 MCP 的几何、关键形、结构、顶点组、路径等编辑因此不触发生成；改变生成输入、改写较早条目、拆分与模拟烘焙仍经基础 Rig（按需生成后重放）。

**与设计的差异**

- 作者态 Rig 放在独立的 `rig/` 目录，没有写进修订索引、也没有提升修订 schema：旧的 v2 程序仍能打开新归档（丢弃该目录）。条目缺失或无法使用时退回生成与重放，因此它目前是“有则优先”的数据，而非唯一权威。
- 生成快照 G 尚未保存（阶段 4 使用）。

**未实现**：阶段 3 的其余部分（改写较早条目的编辑、模拟烘焙与拆分捕获改用作者态 Rig）、阶段 4（再生成合并）、阶段 5（清理）。

**实测**（含 6 个修订的一个用户工程，无骨架）：头部修订由生成与重放构建约 2.2 s，由保存的作者态 Rig 冷打开并构建约 0.4 s，IR 哈希一致；归档增加约 0.3 MB。

**测试**：`MaterializedPreviewTest`（作者态 Rig 构建与完整构建的 IR 哈希一致、不生成基础 Rig、纹理集不同则拒绝、追加条目不需要基础 Rig）、`MaterializedRigProjectTest`（保存后冷打开各修订均由作者态 Rig 构建且一致；日志已无法重放的修订仍可由作者态 Rig 打开）、`RigIrBinaryTest`（对象拆分、拼回、共享与拒绝）、`SkeletonCanvasSkinTest`、`HairSimulationSplitTest`。
