# 文档层：生成器与覆盖（样板）

格式设计把工程定义为“意图 + 用户覆盖”：生成器只保存参数，生成结果由纯函数算出，用户在生成结果上的修改按稳定 ID 记录，生成器重跑时做三方合并。本页记录以摆动生成器为样板的第一阶段实现与评估，它是决定是否在全部生成器上推开的关卡。

## 已实现

| 部分 | 位置 | 内容 |
| --- | --- | --- |
| 内容哈希 | `format-compile` `document/ContentHash` | 各部分规范文本的 SHA-256，按长度分隔，IR 值可直接哈希 |
| 依赖图 | `document/GeneratorGraph` | 生成器声明读取与拥有的稳定 ID；拓扑排序、禁止环、一个对象只能有一个拥有者；给出变化后需要重算的下游生成器 |
| 生成缓存 | `document/GenerationCache` | 按输入内容哈希缓存生成结果（LRU） |
| 三方合并 | `document/ThreeWayMerge` | 逐键合并：用户未改的跟随生成器，生成器未变的保留用户值，两边都改且不同时保留用户值并报告冲突 |
| 生成结果覆盖 | 根项目 `core/GeneratedOverrides` | 摆动生成的 Warp 关键形上的画布编辑记录为 `generated_override`，在所有生成器之后按控制点三方合并重放 |

以上四个框架部分为 MIT，不依赖任何 GPL 模块。

## 生成结果覆盖

- 摆动拥有其参数轴在目标 Warp 上增加的关键形。此前在这些关键形上的画布编辑会写成普通 `canvas_geometry`，重放时摆动参数尚不存在，整个重建失败，编辑无法提交。
- 现在画布编辑若落在“未烘焙摆动的目标 Warp、键中摆动参数不在默认值”的格点上，提交时改写为 `generated_override`：记录生成器、目标、完整键、当时生成的格子（base）与用户格子（points）。
- 重放在摆动与模拟生成之后执行：每个控制点独立合并。改变摆动形状后，用户没动过的点跟随新结果，用户动过而生成器未改的点保持，两边都改的点保留用户位置并报告冲突。
- 摆动被删除、烘焙或改变轴后，键不再对应生成的格点，覆盖不生效并报告为孤立，不会落到其下的静止格子上。
- 摆动参数在默认值处的编辑仍是普通格子编辑，修改的是静止形状。
- 旧工程中的命令不变；只有新的提交会写出覆盖。

## 测量与评估

| 项目 | tml，两个摆动 |
| --- | --- |
| 摆动生成 | 2.8 ms |
| 朴素哈希其输入（IR 文本） | 8.4 ms |
| 全部编辑重放 | 3.8 ms |

摆动生成比为它算哈希更便宜，因此**没有给摆动接入生成缓存**：缓存只适合生成代价远高于输入哈希的生成器（如骨骼蒙皮、物理拟合、模拟烘焙）。目前提交延迟的主要来源是基础 Rig 的重复生成，已通过生成几何缓存解决，见 `GeneratedGeometryCache`。

关卡评估：

- 覆盖与三方合并在摆动上可行，并修复了无法在摆动姿势上编辑的问题；同一机制可直接推广到其他“拥有关键形”的生成器（骨骼修正、身体呼吸等），前提是各生成器声明其拥有的轴。
- 全面声明式化（工程格式 v2、按节点存储、打开时不重放）收益主要在长期可复现性，而非性能；在提交路径已不再重复生成基础 Rig 后，建议先把覆盖机制推广到其余生成器，再迁移存储格式。

## 后续
