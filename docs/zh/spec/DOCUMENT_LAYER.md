# 文档层：生成器、覆盖与缓存

格式设计把工程定义为“意图 + 用户覆盖”：生成器只保存参数，生成结果由纯函数算出，用户在生成结果上的修改按稳定 ID 记录，生成器重跑时做三方合并。第一阶段以摆动生成器为样板验证了机制；本页记录推广到其余生成器、按测量接入生成缓存，以及工程格式 v2 的实现状态。

## 已实现

| 部分 | 位置 | 内容 |
| --- | --- | --- |
| 内容哈希 | `format-compile` `document/ContentHash` | 各部分规范文本的 SHA-256，按长度分隔，IR 值可直接哈希 |
| 依赖图 | `document/GeneratorGraph` | 生成器声明读取与拥有的稳定 ID；拓扑排序、禁止环、一个对象只能有一个拥有者；给出变化后需要重算的下游生成器 |
| 生成缓存 | `document/GenerationCache` | 按输入内容哈希缓存生成结果（LRU）；未命中时在锁外计算，慢生成器不阻塞其他键 |
| 三方合并 | `document/ThreeWayMerge` | 逐键合并：用户未改的跟随生成器，生成器未变的保留用户值，两边都改且不同时保留用户值并报告冲突 |
| 文档生成器图 | 根项目 `core/DocumentGenerators` | 把工程的生成器登记为依赖图节点；重放按图的顺序运行摆动与模拟；覆盖按图查找关键形的拥有者 |
| 生成结果覆盖 | `core/GeneratedOverrides` | 摆动 Warp 关键形与烘焙模拟网格关键形上的画布编辑记录为 `generated_override`，在所有生成器之后按控制点 / 顶点三方合并重放 |
| 骨架与动作缓存 | `core/SkeletonRig.generate`、`core/MotionPresets.tracks` | 骨架烘焙与生成动作按输入内容哈希接入 `GenerationCache` |
| 重放检查点 | `core/ReplayCheckpoints` | 按基础 Rig 实例与日志前缀内容缓存重放的中间模型；追加只重放新条目，撤销命中已有检查点 |
| 生成器复用 | `core/DocumentGenerators`（`GeneratorReuse`） | 摆动与模拟声明对象级读取；读取不变时把上次输出作为补丁套用，不重新生成 |
| 工程格式 v2 | `project/ProjectFormatV2` | 每个修订拆为按内容寻址、带 schema 版本的文档节点；v1 打开后在下次保存时迁移，见[工程格式](PROJECT_FORMAT.md) |

`format-compile` 中的四个框架部分为 MIT，不依赖任何 GPL 模块。

## 生成器依赖图

`DocumentGenerators.graph` 为每个工程构造如下节点（对象 ID：`document:<部分>` 为文档状态，`rig:<阶段>` 为整体 Rig 阶段，`parameter:<ID>` 为生成的参数，`keyform:<warp|mesh>:<目标>@<参数>` 为生成器沿该参数在目标上增加的关键形）：

| 节点 | 读取 | 拥有 |
| --- | --- | --- |
| `rig`（Rig 生成） | 源图、设置、图层分类 | `rig:base` |
| `skeleton`（骨架烘焙） | `rig:base`、骨架定义 | `rig:skeleton` |
| `journal`（编辑重放） | `rig:skeleton`、编辑日志 | `rig:authored` |
| `swing:<ID>`（每个未烘焙摆动） | `rig:authored`、该摆动的设置 | 其参数，及其参数在每个目标 Warp 上的关键形 |
| `simulation:<ID>`（每个已烘焙且启用的模拟） | `rig:authored`、该模拟的设置与烘焙 | 其模式参数，及模式参数在烘焙网格上的关键形 |
| `overrides`（覆盖合并） | 所有生成的关键形、覆盖、生成器集合 | `rig:final` |
| `physics`（物理组） | `rig:final`、生成的参数、物理与骨架设置 | `physics` |
| `motions`（生成动作） | `rig:final`、`physics`、动作设置、骨架定义 | `motions` |

- 重放（`RigEditOverlay.applyTo`）按图的拓扑顺序运行摆动与模拟节点，与此前“先全部摆动、再全部模拟”的顺序一致；声明顺序打破平局。
- 文档若让两个生成器声明同一参数，先声明者保留拥有权，后者的声明被丢弃，重建仍可进行，冲突由生成器自身报告。
- `DocumentGenerators.stale(before, after)` 给出一次文档变化后需要重跑的生成器：读取了变化部分的生成器及其全部下游；被修改或删除的生成器原先拥有的对象也视为变化。例如调整一个摆动只重跑该摆动、覆盖合并、物理与动作，不重跑 Rig 生成、骨架或其他模拟。
- Rig 生成（`RigBuilder` 的网格、变形器、面部等阶段）目前作为一个节点；其内部阶段未拆为独立节点。

## 增量重放

`RigEditOverlay.applyTo` 依次执行旧格式静态编辑（参数删除/创建、静态 Warp、结构、关键形 set/copy/delete）、`authoringJournal` 各条目、摆动与模拟、覆盖合并和延后的面板编辑。前两步是基础 Rig 和条目的纯函数，由 `ReplayCheckpoints` 缓存中间结果；后两步由 `GeneratorReuse` 按读取集复用。

**重放检查点**

- 检查点是“旧格式静态编辑 + 前 `i` 条日志”之后的模型。查找条件：基础模型是同一个实例；旧格式部分相等（含摆动/模拟参数集合，它决定结构编辑哪些延后，以及界面语言）；前 `i` 条每条都与检查点重放过的条目相同（先比引用，不同再比内容）。
- 失效只看前缀内容，不看下标。改写较早条目的命令（拖动合并、生成结果覆盖的捕获、网格规范化）会让该条及之后的检查点自然失配，从最近的有效检查点重放。
- 每条链保留下标 0、每 16 条以及最后 3 条的状态，均为软引用（内存紧张时释放）；最多保留 4 条链（最近使用优先）。分支时保留旧链，供重做或切回使用。
- 追加一条只重放这一条；撤销到前一个状态直接命中，不重放。完整重建（重开、绘画、换图）产生新的基础 Rig 实例，从头重放。
- `PuppetModel` 及其对象按不可变值共享。`-Dpsd2live.replayCheckpoints=false`（或 `ReplayCheckpoints.enabled = false`）同时关闭检查点和生成器复用。

**生成器复用**

- 摆动读取：每个目标 Warp 及其全部祖先（测量所在的父级空间）、参数列表与参数树、世界原点（自动支点）。写入：自己的参数、参数树和目标 Warp。
- 已烘焙模拟读取：目标网格和烘焙网格（几何、混合形、通道）、参数列表与参数树、运行时目标（决定是否用混合形）。写入：自己的参数、参数树和这些网格。
- 生成器运行后，其输出记录为补丁：新的参数列表和参数树，加上被替换的对象。记录前校验：只改了读取集中的对象，其余字段引用不变；否则不缓存。
- 设置相同、读取集逐项相同（先比引用，不同再比内容）时，直接把补丁套到当前输入上，读取集之外的对象保持当前值。比较引用几乎没有成本；按内容哈希读取集反而比生成器本身更贵（见下表）。
- 内容比较只会漏判（数组字段按引用比较），不会误判：漏判只是重新生成。
- `DocumentGenerators.stale` 仍给出文档级的重跑范围；重放时以更细的对象级读取比较为准，例如编辑无关网格时摆动和模拟都复用，编辑摆动目标 Warp 或其祖先时只重跑该摆动。

**效果**（`CommitPerfTool.baseline`，同机前后对比；“关闭”指关闭检查点与生成器复用，“追加”指先重放去掉最后一条的日志，再重放完整日志）：

| 场景 | 此前重放 | 关闭 | 追加一条 | 重复重放同一文档 |
| --- | ---: | ---: | ---: | ---: |
| 场景 a（骨架 + 两个摆动 + 烘焙模拟） | 约 3.7 ms | 约 4.3 ms | 约 1.0 ms | 约 0.6 ms |
| 日志 64 条 | 约 16 ms | 约 20 ms | 约 0.7 ms | 约 0.1 ms |
| 日志 214 条 | 约 43 ms | 约 45 ms | 约 0.4 ms | 约 0.1 ms |

追加 200 条几何编辑后，单次提交从约 98 ms 降到约 46 ms，提交内的重建从约 79 ms 降到约 23 ms；剩下的主要是 moc3 打包和几何安全检查，不再随日志长度增长。

**正确性**：`ReplayCheckpointsTest`（在 `quickTest` 中）在 tml 上带一个摆动和一个烘焙模拟，随机执行 40 步追加网格/Warp 几何、通道关键形、撤销 1–3 步、原位改写较早条目、调整摆动和更换烘焙。每一步比较增量结果与关闭缓存的完整重放，要求 IR 内容哈希相同。另有定向测试：追加只重放 1 条；撤销不重放；改写较早条目从该条或更早处开始；编辑无关网格时两个生成器都复用；编辑摆动目标 Warp 或模拟网格时只重跑对应的生成器。

## 生成结果覆盖

- 关键形的拥有者由图决定：编辑的键中某个参数离开默认值，且图中有生成器拥有 `keyform:<类型>:<目标>@<该参数>`，该格点就是生成的格点。
- **摆动**：拥有其参数轴在目标 Warp 上增加的关键形。覆盖记录生成器、目标 `warp:<ID>`、完整键、当时生成的格子（`base`）与用户格子（`points`），逐控制点合并。
- **烘焙模拟**：拥有模式参数在烘焙网格上的关键形（以关键形轴写回的模拟；以混合形写回时网格格子里没有该轴，编辑不会被识别为覆盖）。覆盖记录目标 `mesh:<ID>`、当时生成的顶点偏移（`base`）与用户编辑后的偏移（`points`，由在当前模型上套用该画布编辑得到），逐顶点合并。重新烘焙或改变增益后，用户没动过的顶点跟随新烘焙，用户动过而烘焙未改的顶点保留，两边都改的保留用户值并报告冲突。
- 此前在这些关键形上的画布编辑写成普通 `canvas_geometry`，重放时参数尚不存在，整个重建失败，编辑无法提交；现在提交时改写为覆盖。
- 生成器被删除、烘焙（摆动）、取消烘焙（模拟）或改变轴后，键不再对应生成的格点，覆盖不生效并报告为孤立，不会落到其下的静止形上。网格重新生成后顶点数变化同样报告为孤立。
- 生成参数在默认值处的编辑仍是普通编辑，修改的是静止形状。旧工程中的命令不变；只有新的提交会写出覆盖。
- 覆盖不影响基础 Rig 生成：生成几何缓存的键忽略覆盖命令，增删覆盖不会让基础 Rig 重新生成。

骨架烘焙的修正关键形没有改为覆盖：骨架在编辑日志之前运行，日志中的画布编辑本来就在骨架之后重放，并会随网格重建一起迁移到新拓扑；改为覆盖反而会在重新划分网格后变成孤立。物理组与生成动作沿用已有的整体覆盖（同 ID 的用户物理组取代生成组，`builtin` 动作片段取代生成动作）。

## 测量与生成缓存

`GeneratorCostTool`（`PSD2LIVE_TOOLS=1`）在 tml 上测量各生成器与对其输入做内容哈希的耗时，输出 `build/tools/generator-cost/report.txt`：

| 项目 | 生成 | 输入哈希 | 结论 |
| --- | --- | --- | --- |
| 骨架烘焙（自动骨架） | 约 4.7 s | 约 5 ms（基础 Rig 的 IR + 骨架定义） | 接入缓存，命中后 Rig 生成约 20 ms |
| 生成动作（全部预设，含骨架预设） | 约 16 ms | < 1 ms | 接入缓存，命中后约 1 ms；Rig IR 编译从约 16 ms 降到约 2 ms |
| 摆动（两个） | 2.8 ms | 8.4 ms | 不做内容哈希缓存；按对象级读取集比较引用后复用输出补丁（见[增量重放](#增量重放)） |
| 烘焙模拟写回 | 约 0.8 ms | 约 8.6 ms（烘焙 JSON） | 同上 |
| 物理组目录 | 约 0.1 ms | 约 0.1 ms | 不缓存 |
| 模拟烘焙本身 | 约 13 s | — | 显式操作，结果已保存在文档中，不重算 |

- 骨架缓存键只含烘焙实际读取的内容：骨骼绑定的网格（完整，含已绑定的页 UV）；挂骨骼、弯曲 Warp 与绑定网格所用的变形器（身体、呼吸、倾斜、腿部 Warp，头部旋转，骨骼自身 ID，绑定网格的父级）及其全部祖先；参数、部件、Glue 与参数树；其余变形器和 Drawable 只取 ID、种类、顺序与父级；另含骨架定义、身体框、绑定网格中的手工拓扑、站姿和界面语言（生成的变形器与参数名称已本地化）。纹理集、源文件与变形路径既不读也不写，不入键。命中但基础 Rig 不同时，未读取的变形器与 Drawable（按烘焙时的改挂父级）、纹理集、源文件与路径取自新基础 Rig，并重新推导绘制顺序；烘焙若以其他方式改动了未读取对象，该结果只对整个 IR 相同的基础 Rig 命中。缓存保留最近 4 个结果。撤销、历史切换、导出前后重复生成同一 Rig，以及骨骼未绑定网格的拓扑编辑或网格设置（不改变身体框时）都会命中；带骨架的完整预览重建从约 5.4 s 降到约 0.5 s。
- 为使内容哈希稳定，Rig 生成的眼部与嘴唇变形路径改为由网格 ID 和路径角色派生的确定性 ID，此前每次生成都是随机 UUID。
- 生成动作的缓存键包含预设名、骨架定义、调整值与排除的参数。
- 基础 Rig 自身仍由已有的 `GeneratedGeometryCache`（保存了生成输入的工程）和快速重放路径处理。前者保留最近 4 个结果（只有最新一个强引用，其余为软引用，内存紧张时释放），撤销与历史切换回到近期输入时复用。
- `canvas_geometry` 日志条目从版本 2 起保存相对执行位置几何的稀疏量化增量（`v`、`n`、`q`、可选顶点索引 `i`、整数增量 `d`），生产方仍提交绝对点，由 `RigAuthoringJournal.compile` 编码，预览与提交应用的都是解码后的命令；版本 1 的绝对点照常重放。
- 编辑器预览的 moc3 包不再回读校验（`validateBundle`），写给用户的导出仍校验；测试 JVM（启用断言）或 `psd2live.validatePreviewBundles=true` 时预览同样校验。
- moc3 包中 physics3/motion3 的生成与规范化（展开指数的正则替换）此前约 18–21 ms，占整包近一半；`Moc3Target` 按输入（物理组、动作、参数集合、文件名前缀）缓存最近 4 份文本，几何编辑不改变这些输入。Rig IR 编译的动作列表同样按输入缓存最近 4 份，此前每次编译都为每个预设序列化骨架定义查生成动作缓存（约 2.5 ms，IR 编译 2.9 → 0.3 ms）。`POS_VALUES` 先算出总长再整块写入，写入器在大小恰好时直接交出缓冲区而不再复制（tml 骨架 Rig 的 moc3 约 7 MB，写出 13.7 → 6.8 ms）。整包从约 48 ms 降到约 20 ms，导出逐字节不变（`ExportGoldenTool`）。逐 Drawable 的 IR 缓存没有做：`PuppetIr.toIr` 只包装数组，约 0.2 ms。
- 几何安全检查比较对象时不再把每个网格和变形器的几何装箱成列表：同一实例直接视为相同，其余按数组逐位比较。逐坐标采样复用每个目标的参考面积与有效性检查，网格采样跳过选择器用的归一化域，基线与候选点相同时复用状态。完整报告与此前逐字节一致（`SafetyGoldenTool` 核对 24 组随机编辑），普通网格编辑从约 15–30 ms 降到 2 ms 以内；绑定骨骼、组合域被采样到 16384 个坐标的网格仍需约 1 s（此前约 2–3 s）。提交另按新增日志命令缩小比较范围，规则见 [MCP_AUTHORING.md](../agent/MCP_AUTHORING.md#几何检查与试运行)。
- Rig 生成不读取纹理集布局：`RigBuilder` 先生成未绑定 Rig（`BuiltRig.unbound`），网格的纹理坐标是顶点相对图层矩形左上角的画布单位偏移，纹理集只有不带放置的图块、没有页面；随后 `UvBinding` 按当前放置换算成页 UV 并写入页面与图块。同一组图层换一种排布时，未绑定 Rig 及其内容哈希不变，只有绑定结果改变。使用偏移而非 0..1 图层单位，是为了让绑定逐位复现原有的页 UV（导出逐字节不变）。骨架目前仍在绑定后烘焙，因为关节细分按 UV 插值新增顶点。canvas、偏移、栅格与页 UV 之间的换算统一由 `LayerTexture` 提供（绘画重映射、生成 Rig 重排到当前纹理、网格迁移日志与 CMO3 导入共用）。

## 性能基线

`CommitPerfTool.baseline`（`PSD2LIVE_TOOLS=1`）在 tml 上搭建带自动骨架、两个摆动（前发、头饰）和一个已烘焙后发模拟的工程，逐阶段测量提交路径，输出 `build/tools/commit-perf/baseline.json` 与 `baseline.md`。数字取自一台 Windows 开发机的单次运行，只用于同机前后对比：不同机器、JIT 预热和并发负载下绝对值可差一倍以上，阶段之间的比例更可靠。阶段值为多次热调用的均值；提交值为经应用层命令边界的墙钟时间（含每次提交后写入历史存储）。原生 Cubism 预览重载需要原生运行时与 GL 上下文，未测；只测了重载前写出运行时文件（“写出”）。

| 场景 | 提交耗时 | 主要构成 |
| --- | --- | --- |
| 完整重建（重开、历史切换、绘画后的重建；骨架缓存命中） | 约 0.7–1.7 s | 纹理集打包约 0.5 s，其中 PNG 编码约 0.43 s；moc3 打包约 35–50 ms；分析约 45–65 ms；无骨架的基础 Rig 约 20–30 ms；骨架命中约 1–7 ms；重放（含摆动/模拟写回约 1–2 ms）约 3–8 ms；IR 编译约 1–4 ms；`validateBundle` 约 1 ms |
| 骨架缓存未命中 | 另加约 5.5–7 s | 骨架烘焙 |
| 几何提交（792 顶点网格） | 约 90–180 ms，中位约 150 ms | 快速路径重建约 55–70 ms（moc3 打包约 36–49 ms、重放约 5 ms、IR 约 3 ms）；几何安全检查约 30–50 ms；历史存储写入约 34 ms；修订号哈希每次提交 4 次，共约 3–7 ms；桌面另写出运行时文件约 28 ms |
